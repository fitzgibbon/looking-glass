* Top

~looking-glass-json-schema~ compiles a JSON Schema into one pure conversion
optic for a complete parsed document.  Each schema node receives its own
converter; object, array, tuple, reference, and union converters compose those
children into the root converter.

The package does not parse or serialize document JSON.  Compose its converter
with ~lg-json-parse~ or ~lg-json-parse-with~ when text input is required.

#+begin_src emacs-lisp
(require 'looking-glass-json-schema)
#+end_src

* Compile a complete-document converter

~lg-json-schema-compile~ accepts raw schema JSON or a schema parsed into a hash
table, alist, or plist.  ~lg-json-schema-converter~ returns the root optic.

#+begin_src emacs-lisp
(let* ((schema
        '(:properties
          (:created (:type "string" :format "date")
           :events
           (:items
            (:properties
             (:when (:type "string" :format "date")))))))
       (set (lg-json-schema-compile schema :object-type 'plist))
       (converter (lg-json-schema-converter set)))
  (lg-view converter
           '(:created "2025-01-02"
             :events [(:when "2025-02-03")])))
;; => (:created #s(lg-json-schema-date 2025 1 2)
;;     :events [(:when #s(lg-json-schema-date 2025 2 3))])
#+end_src

The backward direction converts the complete semantic value to JSON-native
data:

#+begin_src emacs-lisp
(let* ((set (lg-json-schema-compile
             '(:properties (:on (:format "date")))
             :object-type 'plist))
       (converter (lg-json-schema-converter set))
       (semantic
        (list :on (make-lg-json-schema-date
                   :year 2025 :month 7 :day 4))))
  (lg-review converter semantic))
;; => (:on "2025-07-04")
#+end_src

Converters assume that their input satisfies the schema.  This makes an
asserted format conversion total over its intended domain.  Invalid direct
input can signal an error because ordinary plists, alists, and hash tables do
not carry evidence that validation has occurred.

* Compose parsing externally

The same converter works with any compatible parsing prism:

#+begin_src emacs-lisp
(let* ((set (lg-json-schema-compile
             "{\"properties\":{\"on\":{\"format\":\"date\"}}}"))
       (semantic-json
        (lg-compose lg-json-parse
                    (lg-json-schema-converter set))))
  (lg-view semantic-json "{\"on\":\"2025-07-04\"}"))
;; => hash table whose "on" value is #s(lg-json-schema-date 2025 7 4)
#+end_src

Review performs semantic conversion followed by JSON serialization:

#+begin_src emacs-lisp
(let* ((set (lg-json-schema-compile
             '(:properties (:on (:format "date")))
             :object-type 'plist))
       (semantic-json
        (lg-compose (lg-json-parse-with 'plist 'array :null lg-false)
                    (lg-json-schema-converter set)))
       (document
        (list :on (make-lg-json-schema-date
                   :year 2025 :month 7 :day 4))))
  (lg-review semantic-json document))
;; => "{\"on\":\"2025-07-04\"}"
#+end_src

* Compose ordinary field optics after conversion

The root converter is an ordinary iso.  Drill into its semantic result using
existing looking-glass optics:

#+begin_src emacs-lisp
(let* ((set (lg-json-schema-compile
             '(:properties (:born (:format "date")))
             :object-type 'plist))
       (born
        (lg-compose (lg-json-schema-converter set)
                    (lg-plist-key :born)))
       (leap-day
        (make-lg-json-schema-date :year 2000 :month 2 :day 29)))
  (lg-set born leap-day '(:born "1999-12-31")))
;; => (:born "2000-02-29")
#+end_src

The update enters the semantic document through the schema converter, changes
the date with the ordinary plist optic, then reviews the complete result back
to native JSON data.

* Recursive composition

The compiler builds converters according to the current schema node:

- unannotated scalar nodes use ~lg-id~;
- supported ~format~ annotations use registered scalar isos;
- ~properties~ lift child converters through keyed optics;
- schema-valued ~items~ lifts one child through ~lg-vector~ or ~lg-list~,
  starting after any ~prefixItems~;
- ~prefixItems~ and legacy array-valued ~items~ lift positional children
  through ~lg-nth~;
- ~$ref~ reuses the referenced converter;
- ~allOf~ composes all child converters;
- ~oneOf~ and ~anyOf~ select a child converter using a constant discriminator
  when available, then a basic ~type~ check, then declaration order.

Distinct object fields are converted independently.  Backward conversion
visits the same children in reverse composition order.

** Arrays nested in objects

#+begin_src emacs-lisp
(let* ((schema
        '(:properties
          (:teams
           (:items
            (:properties
             (:founded (:format "date")))))))
       (converter
        (lg-json-schema-converter
         (lg-json-schema-compile schema :object-type 'plist))))
  (lg-view converter
           '(:teams [(:founded "1843-01-01")
                     (:founded "1886-01-01")])))
;; => both :founded values become lg-json-schema-date records
#+end_src

** Tuples

#+begin_src emacs-lisp
(let* ((schema
        '(:properties
          (:period
           (:prefixItems [(:format "date") (:format "date")]))))
       (converter
        (lg-json-schema-converter
         (lg-json-schema-compile schema :object-type 'plist))))
  (lg-view converter '(:period ["2025-01-01" "2025-12-31"])))
;; => (:period [#s(lg-json-schema-date 2025 1 1)
;;              #s(lg-json-schema-date 2025 12 31)])
#+end_src

* Reusable definition converters

Converters for root ~$defs~ entries are retained in the compiled set.  This
makes schema reuse visible without generating global variables.

#+begin_src emacs-lisp
(let* ((schema
        '(:$defs
          (:event (:properties (:on (:format "date"))))
          :properties
          (:event (:$ref "#/$defs/event"))))
       (set (lg-json-schema-compile schema :object-type 'plist))
       (event-converter (lg-json-schema-converter set "event")))
  (list (lg-json-schema-definitions set)
        (lg-view event-converter '(:on "2025-05-06"))))
;; => (("event") (:on #s(lg-json-schema-date 2025 5 6)))
#+end_src

Local references are supported, including recursive references over finite
values.  External references signal rather than performing file or network
access.

* Tagged unions

For the common tagged-object case, each alternative converter is selected by
a property with a ~const~ value:

#+begin_src emacs-lisp
(let* ((schema
        '(:oneOf
          [(:properties
            (:kind (:const "started")
             :at (:format "date-time")))
           (:properties
            (:kind (:const "scheduled")
             :on (:format "date")))]))
       (converter
        (lg-json-schema-converter
         (lg-json-schema-compile schema :object-type 'plist))))
  (lg-view converter
           '(:kind "scheduled" :on "2025-08-09")))
;; => (:kind "scheduled" :on #s(lg-json-schema-date 2025 8 9))
#+end_src

The discriminator is retained in the semantic value, so backward conversion
selects the same alternative.  This is conversion dispatch, not complete JSON
Schema validation.  Untagged alternatives use a basic declared-type predicate
or, when no such predicate exists, the first declared alternative.

* Built-in formats

~lg-json-schema-default-formats~ contains:

- ~date~: full-date text to ~lg-json-schema-date~ records via
  ~lg-json-schema-date-iso~;
- ~date-time~: RFC 3339 text to Emacs time values via
  ~lg-json-schema-date-time-iso~.

Reviews emit canonical text.  Date-time values are emitted in UTC with a ~Z~
offset and only the required fractional-second digits, so original offset and
lexical choices are not preserved.  Emacs time values retain up to twelve
fractional digits; finer source precision is truncated to that limit.

Unknown formats are identity conversions.  Formats are annotations unless the
active JSON Schema dialect and validator assert them; callers are responsible
for matching conversion assumptions to validation policy.

* Custom format optics

Pass an alist from format names to conversion optics.  User entries override
the defaults:

#+begin_src emacs-lisp
(let* ((code-iso (lg-iso #'upcase #'downcase))
       (set
        (lg-json-schema-compile
         '(:properties (:code (:format "company-code")))
         :object-type 'plist
         :formats `(("company-code" . ,code-iso))))
       (converter (lg-json-schema-converter set)))
  (list (lg-view converter '(:code "abc"))
        (lg-review converter '(:code "ABC"))))
;; => ((:code "ABC") (:code "abc"))
#+end_src

A format optic should support both ~lg-view~ and ~lg-review~.  Its forward and
backward functions must be pure.

* Parsed representations

~lg-json-schema-compile~ accepts these document options:

- ~:object-type~: ~hash-table~, ~alist~, or ~plist~;
- ~:array-type~: ~array~ for vectors, or ~list~;
- ~:null-object~ and ~:false-object~: parser sentinels used when dispatching
  alternatives by primitive type.

Because the schema identifies whether each node is an object or array, the
converter can support list arrays alongside alist or plist objects.  Parsing
and serialization choices remain subject to the constraints of the parser
optic the caller composes around it.

All transformations return new values.  Hash tables and containing values are
copied along converted branches; input data is not mutated.

* Validation and laws

The package compiles semantic conversion, not a complete JSON Schema
validator.  The iso laws apply over schema-valid values and semantic values
accepted by every codec.  Canonical formats satisfy round trips up to their
documented canonical representation.

Writes through a converter can still violate unrelated constraints such as
~uniqueItems~, ~dependentRequired~, numeric bounds, or conditional schemas.
Validate at the outer boundary when those guarantees must be retained.
