#+TITLE: looking-glass

Compositional profunctor optics for Emacs Lisp.

~looking-glass~ gives you one language for reading, transforming, and reviewing data across lists, vectors, plists/alists/hash tables, strings, JSON text, and regex matches.

- Express nested edits once, then reuse safely.
- Stay fully pure: transforms return new values, so composition stays predictable.

* Quick examples

** Promote names inside JSON text (no parser boilerplate)

#+begin_src emacs-lisp
(require 'looking-glass)

(let ((json "{\"user\":{\"name\":\"Ada\"},\"active\":true}"))
  (lg-over (lg-compose lg-json-parse
                       (lg-ix "user")
                       (lg-ix "name"))
           #'upcase
           json))
;; => "{\"user\":{\"name\":\"ADA\"},\"active\":true}"
#+end_src

#+RESULTS:
: {"user":{"name":"ADA"},"active":true}

** Convert a complete schema before editing it

#+begin_src emacs-lisp
(require 'looking-glass-json-schema)

(let* ((schema
        "{\"properties\":{\"releases\":{\"items\":{\"properties\":{\"published\":{\"format\":\"date\"}}}}}}")
       (converter
        (lg-json-schema-converter (lg-json-schema-compile schema)))
       (published
        (lg-compose lg-json-parse converter
                    (lg-ix "releases") lg-vector (lg-ix "published"))))
  (lg-over published
           (lambda (date)
             (make-lg-json-schema-date
              :year (1+ (lg-json-schema-date-year date))
              :month (lg-json-schema-date-month date)
              :day (lg-json-schema-date-day date)))
           "{\"releases\":[{\"published\":\"2025-01-02\"}]}"))
;; => "{\"releases\":[{\"published\":\"2026-01-02\"}]}"
#+end_src

The schema compiler recursively converts the complete document.  Ordinary
looking-glass optics then edit its semantic values, while review converts them
back to JSON-native data.  Default codecs cover dates and times, durations,
network addresses, URLs, email and host names, UUIDs, regexes, JSON Pointers,
URI templates, and Base64 content.

** Bulk rewrite only capture groups

#+begin_src emacs-lisp
(require 'looking-glass)
(require 'looking-glass-regex)

(lg-over (lg-compose (lg-regex-all-groups "id=\\([0-9]+\\)" 1)
                     lg-number-string)
         (apply-partially #'+ 100)
         "id=1 id=22 id=333")
;; => "id=101 id=122 id=433"
#+end_src

#+RESULTS:
: id=101 id=122 id=433

** Insert and replace list slices

#+begin_src emacs-lisp
(require 'looking-glass)

(let ((numbers '(1 2 3)))
  (list
   (lg-set (lg-slice 1 1) '(4) numbers)
   (lg-over (lg-slice 1 3)
            (lambda (segment)
              (mapcar (lambda (n) (* n 10)) segment))
            numbers)))
;; => ((1 4 2 3) (1 20 30))
#+end_src

#+RESULTS:
: ((1 4 2 3) (1 20 30))

* Package map

- ~looking-glass.el~: pure optic core, composition, folds, indexed optics, reviews, and law-aligned primitives.
- ~looking-glass-regex.el~: pure regex and text traversals (~lg-regex-all~, ~lg-lined~, ~lg-utf8~).
- ~looking-glass-json-schema.el~: recursive semantic converters compiled from JSON Schema.
- ~laws.org~: law expectations and nil-disambiguation notes.

* MELPA manual publishing

MELPA packages repository contents from the selected branch/commit. It does not build manuals from Org/Texinfo build artifacts.

This repository uses CI to build manuals and a dedicated release branch strategy:

- source manuals live in ~doc/*.org~;
- CI builds ~.texi~, ~.info~, and ~dir~ with ~scripts/build-manuals.sh~;
- the ~melpa-release~ branch mirrors ~main~ plus the generated ~*.info~
  files, so recipes find both sources and manuals (the dry-run workflow
  currently reports the exact commands only);
- release dry-run steps are gated on a successful full test run.

MELPA generates each package's ~-pkg.el~ itself, so none are committed
here. The intended recipes select each package's files explicitly:

#+begin_src emacs-lisp
(looking-glass :fetcher github :repo "fitzgibbon/looking-glass"
               :branch "melpa-release"
               :files ("looking-glass.el" "looking-glass.info"))
(looking-glass-regex :fetcher github :repo "fitzgibbon/looking-glass"
                     :branch "melpa-release"
                     :files ("looking-glass-regex.el" "looking-glass-regex.info"))
(looking-glass-json-schema :fetcher github :repo "fitzgibbon/looking-glass"
                           :branch "melpa-release"
                           :files ("looking-glass-json-schema.el"
                                   "looking-glass-json-schema.info"))
#+end_src

package-build generates the ~dir~ entry from the ~.info~ files, which is
what ~M-x info-display-manual~ needs in installed packages.
